## 1.0.0 发布收尾 · ✅ 已完成（2026-10-07）

用户反馈两处 + 发布准备。

| 项 | 根因 / 做法 | 验证 |
|---|---|---|
| **引擎下拉箭头不转回来** | `popover.js` 给触发器设了 `aria-expanded="true"`，而 `closePopover()` 里**从来没有设回 `false`**；箭头旋转是靠 CSS `[aria-expanded="true"]` 驱动的 → 打开过一次就永远朝上。改成开 / 关成对写，并且只动声明了 `aria-haspopup` 的元素（磁贴那种普通按钮不该带这个属性） | 三种关法各断言一遍（Escape / 点外部 / 选中即关）：`aria-expanded` 回到 `false`、箭头 `transform` 回到 `none`、重复开关第二次仍然有效 |
| **搜索栏一键清空** | 右侧尾槽里放清空键与 `/` 提示**叠在同一格**（`display: grid` + `grid-area: 1/1`），两者互斥：没聚焦显示 `/`，聚焦且有内容显示 ×。用 `visibility` 而不是 `display`/`hidden` 属性 —— 隐藏时既点不到也 Tab 不到，还能留在原槽位做淡入淡出 | 6 种状态组合 + 点清空后焦点仍在输入框、没有误触提交；清空键与提示互换时输入框宽度不变（509px → 509px）、搜索栏无横向溢出 |
| **发布准备** | 版本号 0.1.0 → 1.0.0；新增 `tools/package.py`（按 `manifest.json` 的版本号打 zip，manifest 在根、固定时间戳）与 `CHANGELOG.md`；`dist/` 进 `.gitignore` | zip 里 22 个文件、79KB；包内 `manifest.json` 可解析、版本 1.0.0；html 引用 + 所有 js 相对 import + manifest 图标条目**逐个核对无缺失**；解压后再跑 `node --check` 全过 |

**测试**：一个壳页 **39 条断言全过**，含「控制台零报错」和一条「报错收集器自检」
（先故意 `console.error` 一次，确认收集器真能抓到，免得零报错是假的）。
另出一张视觉截图，确认箭头翻转与 × 的实际观感 —— 数值断言证明不了这个。
`node --check` 15 个模块全过。

**两条假失败（是测试写错，不是代码有问题，记下来免得重踩）**：
1. **Escape 清空那条断言不成立**：我把 `keydown` 派发在 `document` 上，而 `search.js` 判的是

**未验证**：还有两处只能装成扩展肉眼确认 —— 清空键在实际壁纸上的对比度，

## M6 · 每日一言 + 时钟样式 · ✅ 已完成（2026-10-08）

用户当场提的两件事。视觉部分专门出了亮底 / 暗底对照截图 —— 数值断言证明不了观感。

### ✅ T6.1 每日一言（第六个组件）
- **目标**：一张按天轮换的句子卡片，和页面其它组件同一套材质，不抢镜、不拖慢首屏
- **产出**：`js/quote.js`、`newtab.html` 的 `.widget[data-widget="quote"]`、`style.css` 的 `.quote`
- **做法**：
  - 内置 60 句，按「本地日期 → 天数序号」取模：同日同句、跨天换句，纯函数、好测
  - 联网那档走一言 API（`v1.hitokoto.cn`），**按天缓存**；失败记一条「今天失败过」，
    半小时内不再请求 —— 和壁纸 / 图标的缓存套路是同一套
  - 一进来先同步铺内置那句，联网结果回来再替换，所以卡片在任何情况下都不是空的
  - 默认位置 `x: 0, y: 0`（左上角），和左下角的壁纸版权一上一下
- **验证**：见下面的实测记录

### ✅ T6.2 时钟样式可选（六种）
- **目标**：同一个时钟换字体 / 视觉风格，用户自己挑
- **做法**：`CLOCK_STYLES`（`js/clock.js`）+ 每条 `[data-clock-style="…"]` 只写一组 `--clock-*` 变量，
  观感全部由 `.clock-face` 统一消费。**设置面板里的示例挂同一个属性**，所以预览就是真观感，
  不存在第二套会走散的样式
- **六种**：极简（默认，就是原来的观感）/ 醒目 / 衬线 / 数码 / 描边 / 微光
- **验证**：逐个断言 computed style（字体栈 / 字重 / 字号 / 描边宽度 / text-shadow / filter）

## M7 · 一言换句 / 纯文字 + 搜索联想 · ✅ 已完成（2026-10-08）

用户当场提的三件事，每一条都先问清「要的是什么」再动手 —— 第 2 条（每开一次换一句）
和 M6 定下的「按天轮换」是**互相矛盾**的，确认过是要换掉 M6 的做法，不是两档并存。

### ✅ T7.1 每日一言改成纯文字
- **目标**：不要再是一块压在左上角的毛玻璃，观感上「就是两行字」
- **做法**：`newtab.html` 去掉 `glass` 类；`style.css` 里内边距归零、不再要圆角。
  内边距一去，左上角正好落在 `.stage` 的 0,0 上，和左下角的壁纸版权左右对齐
- **连带**：字不再是压在玻璃上，而是直接压在壁纸上，阴影换成磁贴名那一套
  （`0 1px 3px rgba(0,0,0,.92)` + `0 1px 12px rgba(0,0,0,.72)`，比原来那组重一档）；
  出处的颜色从 52% 白提到 66%，没有玻璃托底时 52% 太虚

### ✅ T7.2 每打开一次新标签页换一句
- **做法**：内置那档换「抽签袋」（`js/quote.js` 的 `nextIndex`）——
  洗好一队 0..59，每次取队首，取空才重洗，重洗时排除上一句。
  袋子剩下的写进 `quoteBag`，跨标签页、跨重启接着走
- **为什么不是纯随机**：60 选 1 撞上刚刚那句的概率并不低，「随机」实际观感会变成「经常连着两次一样」。
  抽签袋既保证每次都换，又保证 60 句均匀露一遍
- **联网那档**：句子池 `quotePool`，显示取现成的（零等待），后台补一条；
  池子空了先铺内置那句。两轮补货之间隔 20 秒，一口气开一堆标签页只打一轮

### ✅ T7.3 搜索词联想
- **产出**：`js/suggest.js`（新）、`search.js` 接线、`newtab.html` 的 `#searchSuggest` 浮层、
  `style.css` 的 `.search-suggest`、设置里的开关（`search.suggest`）
- **做法**：按引擎 id 查一张写死的接口表 → `fetch` → 解析 → 去重限长 → 渲染成 `role=option`，
  容器是 `popover.js` 的浮层（宽度对齐搜索框）
- **接口**：百度 `sugrec`（`{g:[{q}]}`）/ Bing `osjson` 与 Google `complete`（`[词, [候选]]`）/
  B站 `suggest`（`{result:{tag:[{term}]}}`）。**一律取纯文本字段**：
  B站返回里的 `name` 带 `<em>` 高亮，只取 `term`
- **几个必要的小细节**：敲完停顿 200ms 才发一次；同一个词在本页问过就不再问（内存 LRU 80 条）；
  输入像网址就不联想（用户要的是直接跳）；`mousedown` 上 `preventDefault`，点候选不会把焦点抢走；
  `aria-expanded` / `aria-activedescendant` 开和关成对写
- **验证**：见下面的实测记录

### 实测记录（2026-10-08）

无头 Chrome 装不了扩展（137+ 收紧了 `--load-extension`），本地 http 服务又没有 `host_permissions`，
所以这一轮的验证方式是**用 CDP 驱动无头 Chrome**（`WebSocket` + `Runtime.evaluate` /
`Input.dispatchKeyEvent` / `Page.captureScreenshot`，脚本跑完即删），必要处加 `--disable-web-security`
绕过 CORS 把联想链路跑通。

| 验证项 | 手段 | 结果 |
|---|---|---|
| 纯文字观感 | 读 computed style + 截图 | 背景 `rgba(0,0,0,0)`、`backdrop-filter: none`、`padding: 0`、矩形落在 (22,16) —— 正是 `.stage` 的内缩 |
| 每开一次换一句 | 连开三次读 `#quoteText` | 三句各不相同；抽签袋连抽 130 次**相邻重复 0 次**，前 60 次覆盖 60 句 |
| 换句的落盘 | 同一 profile 里反复重载 | `quoteBag` 每次少一个、`last` 跟着走，跨页面加载接得上 |
| 一言那档 | 打桩检查池子 + 连开 6 个标签页数请求 | 池子里有现成句子时就显示它（不是先闪内置再换）；爆发 6 次打开**只打了一轮请求**；断网时退回内置句子，从不空着 |

| 请求纪律 | 数 `Network.requestWillBeSent` | 空输入框 + 聚焦 0 条；敲一次 1 条；**退回问过的词 0 条**（内存缓存）；换过的词跨页面加载 0 条（HTTP 缓存）；关掉开关后 0 条 |

| 设置面板 | 截图 + 读文本 | 开关在引擎列表末尾，提示文字跟着开关状态变 |
| 语法 / 冒烟 | `node --check` 全部模块；整页跑三遍 | 全过；除本地服务自己的 `favicon.ico` 404 外**控制台零报错** |

**两条实测与转述 / 直觉不符的**：

1. **一言对短时间内的重复请求返回同一句**。原本打算「一次补三条」把池子填起来 ——
   实测并发三条、串行三条，回来的**逐字一致**，批量补货根本拿不到几份不同的句子。
   改成一次只补一条：池子的价值在「显示不等网络」和「爆发合并」，不在省请求。
   （这条也解释了为什么一开始的验证里池子只进了 1 条 —— 去重把另外两条同句的丢掉了。）
2. **`node` 的 `fetch` 不走系统代理**，而 `curl` 走。同一个 Google 联想接口，`curl` 200、
   `node` 一律 `fetch failed` 超时 —— 一开始差点当成「这个接口坏了」。
   浏览器（以及扩展）走系统代理，所以这一条在墙内能不能用，取决于机器上有没有代理。

**测试规模**：CDP 五个脚本、约 40 条断言全过；`node --check` 17 个模块全过。

**未验证**：联想四个接口在**扩展里**的真实可用性（本地是靠 `--disable-web-security` 绕过去的）、
候选浮层在真实壁纸与窄窗口下的观感、一言联网档在弱网下的表现。

顺手修掉的两个老问题：

1. **毛玻璃首帧失效**（人工反馈确认）。根因是 `body.is-booting .stage { opacity: 0 }`：

2. **缩放会把描边一起缩掉**。同一朵云按不同比例复用到 8 个图标，

P1 是拿真机数据标定默认坐标的：最初推算的 `y` 值在 1280×720 下就让时钟和搜索框压在一起，
是截图看出来的。后来改成程序化测量 14 档尺寸，把默认值调成 25 / 50 / 74。

**过程中实测发现并修掉的真问题**：

1. **编辑模式被当成普通浮层**：注册进浮层栈时没区分「模式」和「浮层」，于是
   ① 一按下去拖组件就被「点外部关闭」判定退出、根本拖不动；
   ② 点「+」开表单时 `closeAll()` 把编辑模式一起关掉，表单开出来却已不在编辑态。
   加了 `sticky` 语义（不参与 `closeAll`、不响应点外部）后解决。
2. **`display: none` 的元素 `offsetParent` 是 `null`**：浮层定位在元素显形**之前**取
   `offsetParent`，退化成 `body`，算出来的视口坐标被当成组件本地坐标用，整个浮层偏到天边。
   改成显形之后再取。
3. **浮层被兄弟组件盖住**：组件都是 `z-index: 1`，DOM 靠后的赢，搜索框的下拉被磁贴压住。
   改成浮层打开时把所在组件抬到 `--wz: 20`。
4. **编辑态的点击处理器把「+」吞了**：捕获阶段那个 `stopPropagation()` 让冒泡阶段的
   「打开表单」永远收不到事件。合并成一个按目标分派的处理器。
5. **`requestAnimationFrame` 在无头环境会停摆**：拖拽原本用 rAF 合帧，测试里时好时坏。
   指针事件本来就是每帧至多一次，去掉 rAF 后改同步更新 —— 更简单，也可测。

**两条写进 AGENTS.md 硬性约束的结论**：
- 编辑态的虚线框必须用 `outline` 不能用 `border`（border 改变 `offsetWidth`，组件会跳一下）
- 压暗「已隐藏」的组件必须用 `::after` 蒙层不能用 `opacity`（会让里面的毛玻璃整块失效）
- WAAPI 的 `el.animate()` **不受** CSS 的 `prefers-reduced-motion` 全局规则约束，得自己判

**测试方法上的两个坑**（记下来免得重踩）：
- 合成事件是**不可信**的：`dispatchEvent` 触发不了 `<dialog>` 的原生 Escape 行为，
  也触发不了 `setPointerCapture`（会抛 NotFoundError，代码里已兜住）。
  所以 Escape 关设置这条只能断言「我们的捕获监听放行了」，真实关闭靠人工确认。
- 在测试里对磁贴派发真实 click 会把 iframe **导航到外站**，之后整个 iframe 变跨域、
  后续断言全崩。要改成同页 hash 导航（只改 hash 不会重新加载文档）。

**未验证**：拖拽手感、吸附辅助线观感、毛玻璃在各浮层上是否一致 —— 需装扩展肉眼确认。

**两个 bug 的根因都是实测出来的，不是猜的**：

1. **拖动时磁贴飘走**。写了复现壳页量数据：拖动中磁贴左上角比指针多出 **270, 522.6**，

### M5 补充（2026-10-07）：图标改走第三方服务 + 磁贴默认新标签页

用户提了两件事：点击图标改为默认在新标签页打开；图标获取改用两个国内接口。
接口格式先逐个核实过，**有两处和转述不符**，都按实测改了：

| 接口 | 转述 | 实测 |
|---|---|---|
| Cravatar | `?url=目标网站域名` | 参数名对，但**只吃纯域名** —— 带上 `https://` 或路径直接返回 504 |
| Cravatar | —— | 响应头 `X-Favicon-State` 会说这张图是什么：`ready` 是真图标，`fallback` 是「还没抓到，先给占位图」。且 `ready` 的字节和站点自己的 `/favicon.ico` **完全一致**（bilibili `f2d2896c…`、知乎 `ce3eb40c…`，两边 md5 相同） |
| 0x3 | `?host=目标网站域名`，没有跨域限制 | 参数名对；但它**不返回任何 CORS 头**，只是自己不做限制 —— 跨域读响应仍会被浏览器拦，只有扩展的 `host_permissions` 能豁免 |
| 0x3 | —— | **拿不到图标时照样返回 200**，内容是一张固定的 794 字节 SVG 链接图标，随便编三个域名逐字节完全一致。不比对就会让一排站点全长一样 |

最终链路：自传图标 → `_favicon`（本地缓存，零请求）→ 自存缓存 → **Cravatar → 0x3 →
站点 `/favicon.ico` → 页面声明的 `<link rel=icon>`** → 首字母色块。本地/内网地址不发去第三方。

**过程中挖出的一个真问题**：第一次跑，8 个默认站点只有 **3 个**拿到图标，其余全被负缓存。
十分钟后再跑，**8/8**。原因是 Cravatar 对没缓存的域名一律先返回 `fallback` 占位图、
同时后台去抓 —— 它是「稍后再来」，不是「失败」。按失败缓存 6 小时的话，

也归进 `pending`** —— 那是服务这边的问题，不该记成「这个站点没有图标」。

**验证**：

| 项 | 结果 |
|---|---|
| 新标签页打开 | `target=_blank` + `rel=noopener`；**真实点一次**，iframe 没有被导航走（没加 target 时会把当前页带走），11/11 通过 |
| 服务链路 | github 走 Cravatar 拿到真图标并落盘；编造的域名拿不到图标时**不出现破图**、首字母兜底在、缓存记成 `pending` 而非 `failed` |
| 本地地址 | 不发去第三方，直接取站点 `/favicon.ico`，正常落盘 |
| 默认站点覆盖率 | 冷启动 3/8 → 服务预热后 **8/8** |
| 整页冒烟 | 时钟、8 个磁贴、搜索框、天气全部正常，**控制台零报错** |
